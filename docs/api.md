# API сервера

Все адреса — `http://localhost:4100/api/…` (в режиме разработки интерфейс на 5173 передаёт их серверу). Ответы — JSON; моменты времени — миллисекунды Unix; ошибки — `{ error, details }` с текстом по-русски.

## Главное

| Запрос | Что делает |
|---|---|
| `GET /today` | Главный экран: сегодняшние занятия, следующее, таймер, незаписанный итог, число вопросов, «с чего продолжить». Запускает проверки |
| `GET /stats` | Статистика семестра: прогресс, посещаемость, серия, прогноз, калибровка |

## Настройки

| Запрос | Что делает |
|---|---|
| `GET /settings` | Настройки (до первой записи — значения по умолчанию) |
| `PUT /settings` | Сохранить: окна для учёбы, неудобное время, дни, буфер, лимиты, Помодоро, длина семестра |

## Дисциплины и источники

| Запрос | Что делает |
|---|---|
| `GET /disciplines[?archived=true]` | Список |
| `POST /disciplines` | Создать: название, приоритет, длительность, **цель**, **метрики** |
| `GET /disciplines/:id` | Карточка с источниками и «с чего продолжить» |
| `PATCH /disciplines/:id` | Изменить (приоритет и длительность — не во время семестра) |
| `POST /disciplines/:id/archive` | В архив |
| `DELETE /disciplines/:id` | Удалить карточку и источники из библиотеки; 409 при связи с текущим семестром или черновиком. История занятий и итоги сохраняются |
| `POST /disciplines/:id/sources` | Добавить ссылку (`kind: link, url`) или заметку (`kind: note, note`) |
| `PATCH /sources/:id`, `DELETE /sources/:id` | Изменить или удалить источник |

В `GET /disciplines/:id` поле `deletion` содержит `{ allowed, reason }`: доступно ли удаление и почему оно заблокировано. Удалённая карточка недоступна для просмотра/редактирования и не возвращается в списках, включая архив. Сведения для истории остаются доступны в итогах и экспорте.

## Семестр

| Запрос | Что делает |
|---|---|
| `POST /semesters/draft` | Черновик: `startDate`, `fullWeeks`, `disciplineIds` |
| `GET /semesters/draft`, `POST /semesters/draft/refresh` | Посмотреть или пересчитать черновик |
| `POST /semesters/draft/compromises/:index` | Согласиться на компромисс — черновик строится заново |
| `POST /semesters/draft/confirm` | Подтвердить — семестр начинается |
| `DELETE /semesters/draft` | Удалить черновик |
| `DELETE /semesters/:id` | Удалить семестр вместе со связанными событиями Google; 204 также при повторном удалении отсутствующего семестра |
| `GET /semesters/active` | Идущий семестр: бюджет, каркас, текущая неделя |
| `POST /semesters/active/changes/preview` | «Было → станет» для `add`/`remove` дисциплины |
| `POST /semesters/active/changes/apply` | Применить (с `compromiseIndex`, если без него не помещается) |

Если связь прервалась при удалении событий, семестр возвращается с `deletionPending: true`. Пока удаление не завершено, синхронизация не восстанавливает его события. Повторный запрос продолжает удаление. Успешное удаление снимает прежнюю ошибку Google; API-ответы не кэшируются.

## Расписание и занятия

| Запрос | Что делает |
|---|---|
| `GET /schedule?from=&to=` | Занятия в промежутке |
| `GET /sessions/:id` | Занятие: цель, метрики, источники, «с чего продолжить», итог |
| `POST /sessions/:id/start` | Начать (за 30 мин до начала — до конца) |
| `POST /sessions/unplanned` | Внеплановое занятие: `disciplineId` |
| `POST /sessions/:id/move` | Ручной перенос: `start`; при нарушениях — 409 со списком, `confirm: true` — применить |
| `POST /sessions/:id/skip` | Пропустить заранее |
| `POST /sessions/:id/summary` | Итог: `keyConcepts` и/или `retelling`, `continueFrom` |
| `GET /timer`, `POST /timer/pause`, `/resume`, `/finish` | Таймер Помодоро. Причины автоматической паузы: сон (`sleep`), закрытая страница (`away`) и конец отведённого времени (`deadline`). |
| `POST /timer/resume` с `{ "continueBeyondPlan": true, "sessionId": "…" }` | Продолжает учёбу за пределами плана с момента выбора. |
| `POST /timer/resume` с `{ "countPaused": true }` | «Я занимался — засчитать»: время паузы идёт в учёбу |

## Решения — вопросы сервиса

| Запрос | Что делает |
|---|---|
| `GET /decisions` | Открытые вопросы: пропуски, конфликты, калибровка, контрольные точки — с вариантами |
| `POST /decisions/:id/resolve` | Ответ: `makeup`/`leave`, `move`/`compromise`/`skip`/`keep`/`skeleton`, `accept`/`dismiss`, `ack`/`extend`/`biweekly`/`finish` |

## Опыт, звания и награды

- `GET /progress` — опыт, уровень (1–50), порог следующего уровня, открытые звания, настройки наград, непоказанное начисление, копилка и последние 20 использованных наград. Будущие звания не передаются клиенту.
- `PUT /progress/title` с `{ "level": 0 }` — автоматически показывать последнее звание; 1–50 — закрепить уже открытое звание.
- `POST /progress/rewards` с `{ "title": "Посмотреть серию аниме" }` — добавить вариант; `PATCH /progress/rewards/:id` — изменить `title` и/или `enabled`. До 30 включённых вариантов, без одинаковых названий. Заработанные варианты — неизменяемые снимки.
- `DELETE /progress/rewards/:id` — удалить пункт из будущего набора. Заработанные предложения не изменяются.
- `PUT /progress/preferences` с `{ "rewardsEnabled": false, "qualitiesEnabled": true }` — независимо включать приятные награды и находки слов; поля необязательные. Настройки сохраняются между запусками. Полный `GET /progress` возвращает эти флаги, `collectionSize: 500` и `collection` из открытых `{id, word, foundAt}`; неоткрытые слова клиенту не передаются.
- В `StudyAward` поля `qualityOutcome` (`legacy`, `found`, `miss`, `complete`, `disabled`) и `quality` (`null` либо `{id,word}`) — сохранённый результат броска. При включённой коллекции сначала равновероятный бросок 50/50, затем равномерный выбор из ещё не открытых слов. На одно начисление — не более одного слова. После заполнения всей коллекции новые слова не выдаются, опыт и приятные награды продолжают работать. Процентов у приятных наград нет; сохраняется выбор до двух разных случайных вариантов.
- `POST /progress/awards/:id/choose` с `{ "index": 0 }` — выбрать один из заработанных вариантов (0 или 1). Повтор того же выбора безопасен; смена уже выбранного запрещена.
- `POST /progress/awards/:id/use` — отметить выбранную награду использованной; повтор не меняет дату и не создаёт дубль.
- `POST /progress/awards/:id/acknowledge` — закрыть поздравление, сохранив награду в копилке. Работает и до выбора варианта.

Начисление 100 XP выполняется в одной транзакции с новым итогом занятия, если `actualMinutes >= 1`. Уникальная пара семестр/занятие исключает дубли. `nextQuestion` — новое необязательное поле итога (до 2000 символов); `GET /sessions/:id` возвращает вопрос из последнего более раннего занятия этой дисциплины. Эти данные сохраняются после перезапуска. Старые итоги не дают XP автоматически. Общий опыт и копилка не удаляются вместе с семестром. Изменения наград не запускают синхронизацию Google.

## Практика по записям

- `GET /practice/summaries` — сохранённые итоги всех семестров и дисциплин, включая завершённые и архивные; сначала последние по времени занятия. `id` однозначно определяет пару семестр/занятие. Поля: `semesterId`, `sessionId`, `disciplineId`, `disciplineName`, `sessionStart`, `createdAt`, `keyConcepts`, `retelling`, `continueFrom`.
- `POST /practice/prompt` — локальная сборка промпта, без изменения данных и обращения к Google или ИИ. Тело: `summaryIds` (1–100 идентификаторов из списка), `mode` (`single` или `interdisciplinary`), `minutes` (15, 30, 60), `difficulty` (`reinforce` или `challenge`), `wish` (до 2000 символов). Ответ: `{ "prompt": "…" }`. По умолчанию: обычное задание, 30 минут, закрепление основ.
- Междисциплинарный формат требует итогов хотя бы из двух дисциплин. Неизвестные/удалённые записи — 404; некорректные параметры или объём выбранного текста более 180 000 символов — 400. Тексты не обрезаются, повторные идентификаторы не дублируют записи. В инструкции предусмотрены постепенные подсказки и полное решение только по явной просьбе.

## Экспорт и состояние сервиса

| Запрос | Что делает |
|---|---|
| `GET /export/summaries[?format=json]` | Все итоги занятий (Markdown по умолчанию) |
| `GET /health` | Сервер жив, версия движка, есть ли ключи Google; `web` — рабочий режим (сервер отдаёт интерфейс), `pid` — номер процесса в нём |
| `GET /system/shortcuts`, `PUT /system/shortcuts` | Ярлык на рабочем столе и автозапуск с Windows: `{ "desktop": true, "autostart": false }` |

Запросы, которые что-то меняют, принимаются только со страниц самого сервиса (`localhost`): с чужих сайтов — 403.

## Google Календарь

| Запрос | Что делает |
|---|---|
| `GET /auth/google` | Перейти ко входу в Google (открывать в обычном браузере) |
| `GET /auth/google/callback` | Сюда Google возвращает после входа; дальше — на главную с `?google=connected` |
| `GET /google/status` | Подключён ли, кто вошёл, нужен ли повторный вход, когда обновлялась занятость, последняя ошибка; `calendarTimezone` — часовой пояс основного календаря Google (в нём Google показывает занятия) |
| `GET /google/calendars` | Календари и какие из них учитываются как занятость |
| `PUT /google/calendars` | Выбрать календари: `busyCalendarIds` (null — все) |
| `GET /google/busy?days=14` | Что сервис видит как занятость в ближайшие дни |
| `POST /google/sync` | Синхронизировать сейчас |
| `POST /google/disconnect` | Отключить и отозвать доступ |
