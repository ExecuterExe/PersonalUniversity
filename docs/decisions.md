# Принятые решения

Короткий журнал технических решений: что выбрали и почему.

## 24.10.2026 · Этап 0

1. **TypeScript 6.0, а не 7.** TypeScript 7 (новый компилятор) уже вышел, но typescript-eslint пока поддерживает только версии ниже 6.1. Перейдём, когда линтер его поддержит.
2. **npm workspaces: `engine` / `server` / `web`.** Движок подключается как пакет `@ou/engine` прямо из исходников, без отдельной сборки.
3. **Движок без ввода-вывода.** В настройках TypeScript для движка нет типов Node и браузера — случайно обратиться к файлам, сети или странице нельзя. Текущее время передаётся параметром, поэтому тесты всегда дают одинаковый результат.
4. **Сервер слушает только localhost.** Другие устройства в сети его не видят.
5. **Порты:** сервер — 4100 (`SERVER_PORT`), интерфейс в режиме разработки — 5173, запросы `/api` и `/auth` он передаёт серверу. Переменная называется `SERVER_PORT`, а не `PORT`: общий `PORT` выставляют инструменты запуска, и на проверке сервер из-за этого пытался занять порт интерфейса.
6. **Интерфейс явно слушает 127.0.0.1.** По умолчанию Vite на Windows слушал только IPv6-адрес `::1`, и браузер не открывал страницу.
7. **`.env` читается встроенным в Node `process.loadEnvFile`** — без лишней зависимости. `npm run check:env` проверяет ключи Google, не показывая их.
8. **Google-приложение остаётся в режиме Testing.** Для рабочего режима Google требует ссылки на домашнюю страницу и политику конфиденциальности на зарегистрированном домене — у локального сервиса их нет. Цена: доступ истекает каждые 7 дней, поэтому сервис раз в неделю просит войти заново. Если это начнёт мешать — можно сделать мини-сайт (например, на GitHub Pages) и перейти в рабочий режим.
9. **Установочные скрипты пакетов не разрешены.** npm 11 предупредил про скрипт esbuild; без него всё работает — проверено запуском сервера.
10. **Стиль кода:** имена в коде — по-английски; комментарии, сообщения и названия тестов — по-русски.

## 24.10.2026 · Этап 1 — движок расписания

1. **Время — Luxon плюс заранее посчитанные дни семестра.** В обычные дни время считается сложением, в дни перехода на летнее время — через часовой пояс. Это ускорило построение в 10–15 раз (с 1–5 с до 50–400 мс).
2. **Сетка начала занятий — 15 минут.**
3. **Каркас: жадное размещение и локальное улучшение.** Сначала основные, потом дополнительные; затем каждая дисциплина по очереди переставляется целиком, пока растёт общая оценка. Веса мягких целей — `SCORE` в `engine/src/skeleton.ts`.
4. **Не больше 2 занятий в день** — жёсткое правило, как договорились.
5. **Порог устойчивости места — 50% недель.**
6. **Понижение частоты:** основные 3 → 2, начиная с той, что не встала, иначе с самой длинной; при равной длительности — первая по списку.
7. **Компромиссы — по одному ослаблению**, каждый проверяется полным построением. Окно для учёбы можно разрешить одной дисциплине или сразу всем, кто не встал (так сформулировано в методологии). Не больше 2 вариантов одного типа и 6 всего.
8. **Конфликт, которому некуда переехать,** получает компромиссы для одного занятия: провести короче, один раз выйти за окна, один раз превысить дневной или недельный лимит. Согласие записывается в само занятие (`acceptedViolations`) и дальше не всплывает.
9. **Перенос на следующую неделю — только на её первые 3 дня** и только в пределах недельного лимита.
10. **Отработка — в ближайшие 7 дней.** Варианты для каждого следующего пропуска считаются с учётом уже выбранных отработок; если места нет — вариантов нет, правила не нарушаются.
11. **Правило максимального перерыва** учитывается и при переносах, а не только при построении каркаса.
12. **Предупреждение «неделя заполнена до лимита»** — дополнение к резерву: если до недельного лимита меньше самого короткого занятия, отрабатывать пропуски будет некогда.
13. **Калибровка:** предлагается ближайшая допустимая длительность не меньше «медиана + 10 мин» — при среднем 45 из 90 это 60 мин, как в методологии.
14. **Середина семестра** — с начала 7-й недели из 12, то есть после 6 полных недель.
15. **Действия контрольной точки в движке:** продлить семестр (каркас продолжается) и «раз в 2 недели» для дисциплины, что идёт раз в неделю (со следующей недели).

## 24.10.2026 · Приёмка этапа 1

1. **Неудобное время — отдельная настройка (сделать на этапе 2).** Пользователь прямо назвал неудобным утро до 10:00 и вечер 18:50–22:00 (пары). Такое время не должно появляться даже в компромиссах: «другие окна» для компромиссов = части дня минус неудобное время. Сейчас движок берёт их из `otherWindows` как есть.
2. **Семестр, начатый не с понедельника,** — первая неделя неполная и показывается отдельно; при создании семестра длину считаем в полных неделях и добавляем к ним эти дни.

## 24.10.2026 · Этап 2 — данные и сервер

1. **Встроенный SQLite из Node (`node:sqlite`) вместо better-sqlite3 и Drizzle.** better-sqlite3 собирается установочным скриптом, а npm 11 такие скрипты блокирует; встроенный SQLite в Node 24 работает без установки и без сборки. Вместо ORM — тонкий слой с SQL (`server/src/db/store.ts`), миграции — по номеру в `PRAGMA user_version`.
2. **Проверка входных данных — zod**, сообщения об ошибках по-русски.
3. **Неудобное время — без буфера.** Буфер нужен вокруг событий; неудобное время — не событие, а зона, куда просто нельзя ставить. Иначе «утро до 10:00» превращалось в занятость до 10:30.
4. **Прогресс считается в чистом времени учёбы с обеих сторон:** план — сколько учёбы помещается в занятие (90 мин = 75 мин учёбы + перерывы), факт — сколько было. Так прогресс может дойти до 100%. Калибровка сравнивает длительность занятия (с перерывами, без пауз) с планом — «45 из 90 мин».
5. **Идентификаторы занятий — без `/`, `@`, `+`:** `id.1.600.0.w3` — безопасно для адресов API.
6. **Правила семестра = настройки пользователя + то, на что он согласился в компромиссах** (`settingsPatch`, `disciplinePatches` семестра). Поменял настройки — новые правила сразу действуют и в идущем семестре.
7. **Один черновик и один идущий семестр** — ограничение прямо в базе. Новый семестр — только после завершения текущего.
8. **Длина семестра в API — в полных неделях;** если семестр начинается не с понедельника, первые дни добавляются сверху.
9. **Старт занятия:** не раньше чем за 30 минут и не позже его конца; сначала проверяется, не идёт ли другое занятие и записан ли итог прошлого.
10. **Вопрос про конфликт привязан к месту занятия и событиям.** Поменялось одно из них — это новый вопрос; событие убрали из календаря — вопрос закрывается сам.
11. **Любой обзор контрольной точки сбрасывает отсчёт раннего сигнала** — два обзора подряд не нужны.
12. **Резервная копия — `VACUUM INTO`** в `data/backups/ou-ГГГГ-ММ-ДД.sqlite`, раз в день, хранятся 14 последних.
