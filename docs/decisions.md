# Принятые решения

Короткий журнал технических решений: что выбрали и почему.

## 24.10.2026 · Этап 0

1. **TypeScript 6.0, а не 7.** TypeScript 7 (новый компилятор) уже вышел, но typescript-eslint пока поддерживает только версии ниже 6.1. Перейдём, когда линтер его поддержит.
2. **npm workspaces: `engine` / `server` / `web`.** Движок подключается как пакет `@ou/engine` прямо из исходников, без отдельной сборки.
3. **Движок без ввода-вывода.** В настройках TypeScript для движка нет типов Node и браузера — случайно обратиться к файлам, сети или странице нельзя. Текущее время передаётся параметром, поэтому тесты всегда дают одинаковый результат.
4. **Сервер слушает только localhost.** Другие устройства в сети его не видят.
5. **Порты:** сервер — 4100 (`SERVER_PORT`), интерфейс в режиме разработки — 5173, запросы `/api` и `/auth` он передаёт серверу. Переменная называется `SERVER_PORT`, а не `PORT`: общий `PORT` выставляют инструменты запуска, и на проверке сервер из-за этого пытался занять порт интерфейса.
6. **Интерфейс явно слушает 127.0.0.1.** По умолчанию Vite на Windows слушал только IPv6-адрес `::1`, и браузер не открывал страницу.
7. **`.env` читается встроенным в Node `process.loadEnvFile`** — без лишней зависимости. `npm run check:env` проверяет ключи Google, не показывая их.
8. **Google-приложение остаётся в режиме Testing.** Для рабочего режима Google требует ссылки на домашнюю страницу и политику конфиденциальности на зарегистрированном домене — у локального сервиса их нет. Цена: доступ истекает каждые 7 дней, поэтому сервис раз в неделю просит войти заново. Если это начнёт мешать — можно сделать мини-сайт (например, на GitHub Pages) и перейти в рабочий режим.
9. **Установочные скрипты пакетов не разрешены.** npm 11 предупредил про скрипт esbuild; без него всё работает — проверено запуском сервера.
10. **Стиль кода:** имена в коде — по-английски; комментарии, сообщения и названия тестов — по-русски.

## 24.10.2026 · Этап 1 — движок расписания

1. **Время — Luxon плюс заранее посчитанные дни семестра.** В обычные дни время считается сложением, в дни перехода на летнее время — через часовой пояс. Это ускорило построение в 10–15 раз (с 1–5 с до 50–400 мс).
2. **Сетка начала занятий — 15 минут.**
3. **Каркас: жадное размещение и локальное улучшение.** Сначала основные, потом дополнительные; затем каждая дисциплина по очереди переставляется целиком, пока растёт общая оценка. Веса мягких целей — `SCORE` в `engine/src/skeleton.ts`.
4. **Не больше 2 занятий в день** — жёсткое правило, как договорились.
5. **Порог устойчивости места — 50% недель.**
6. **Понижение частоты:** основные 3 → 2, начиная с той, что не встала, иначе с самой длинной; при равной длительности — первая по списку.
7. **Компромиссы — по одному ослаблению**, каждый проверяется полным построением. Окно для учёбы можно разрешить одной дисциплине или сразу всем, кто не встал (так сформулировано в методологии). Не больше 2 вариантов одного типа и 6 всего.
8. **Конфликт, которому некуда переехать,** получает компромиссы для одного занятия: провести короче, один раз выйти за окна, один раз превысить дневной или недельный лимит. Согласие записывается в само занятие (`acceptedViolations`) и дальше не всплывает.
9. **Перенос на следующую неделю — только на её первые 3 дня** и только в пределах недельного лимита.
10. **Отработка — в ближайшие 7 дней.** Варианты для каждого следующего пропуска считаются с учётом уже выбранных отработок; если места нет — вариантов нет, правила не нарушаются.
11. **Правило максимального перерыва** учитывается и при переносах, а не только при построении каркаса.
12. **Предупреждение «неделя заполнена до лимита»** — дополнение к резерву: если до недельного лимита меньше самого короткого занятия, отрабатывать пропуски будет некогда.
13. **Калибровка:** предлагается ближайшая допустимая длительность не меньше «медиана + 10 мин» — при среднем 45 из 90 это 60 мин, как в методологии.
14. **Середина семестра** — с начала 7-й недели из 12, то есть после 6 полных недель.
15. **Действия контрольной точки в движке:** продлить семестр (каркас продолжается) и «раз в 2 недели» для дисциплины, что идёт раз в неделю (со следующей недели).

## 24.10.2026 · Приёмка этапа 1

1. **Неудобное время — отдельная настройка (сделать на этапе 2).** Пользователь прямо назвал неудобным утро до 10:00 и вечер 18:50–22:00 (пары). Такое время не должно появляться даже в компромиссах: «другие окна» для компромиссов = части дня минус неудобное время. Сейчас движок берёт их из `otherWindows` как есть.
2. **Семестр, начатый не с понедельника,** — первая неделя неполная и показывается отдельно; при создании семестра длину считаем в полных неделях и добавляем к ним эти дни.

## 24.10.2026 · Этап 2 — данные и сервер

1. **Встроенный SQLite из Node (`node:sqlite`) вместо better-sqlite3 и Drizzle.** better-sqlite3 собирается установочным скриптом, а npm 11 такие скрипты блокирует; встроенный SQLite в Node 24 работает без установки и без сборки. Вместо ORM — тонкий слой с SQL (`server/src/db/store.ts`), миграции — по номеру в `PRAGMA user_version`.
2. **Проверка входных данных — zod**, сообщения об ошибках по-русски.
3. **Неудобное время — без буфера.** Буфер нужен вокруг событий; неудобное время — не событие, а зона, куда просто нельзя ставить. Иначе «утро до 10:00» превращалось в занятость до 10:30.
4. **Прогресс считается в чистом времени учёбы с обеих сторон:** план — сколько учёбы помещается в занятие (90 мин = 75 мин учёбы + перерывы), факт — сколько было. Так прогресс может дойти до 100%. Калибровка сравнивает длительность занятия (с перерывами, без пауз) с планом — «45 из 90 мин».
5. **Идентификаторы занятий — без `/`, `@`, `+`:** `id.1.600.0.w3` — безопасно для адресов API.
6. **Правила семестра = настройки пользователя + то, на что он согласился в компромиссах** (`settingsPatch`, `disciplinePatches` семестра). Поменял настройки — новые правила сразу действуют и в идущем семестре.
7. **Один черновик и один идущий семестр** — ограничение прямо в базе. Новый семестр — только после завершения текущего.
8. **Длина семестра в API — в полных неделях;** если семестр начинается не с понедельника, первые дни добавляются сверху.
9. **Старт занятия:** не раньше чем за 30 минут и не позже его конца; сначала проверяется, не идёт ли другое занятие и записан ли итог прошлого.
10. **Вопрос про конфликт привязан к месту занятия и событиям.** Поменялось одно из них — это новый вопрос; событие убрали из календаря — вопрос закрывается сам.
11. **Любой обзор контрольной точки сбрасывает отсчёт раннего сигнала** — два обзора подряд не нужны.
12. **Резервная копия — `VACUUM INTO`** в `data/backups/ou-ГГГГ-ММ-ДД.sqlite`, раз в день, хранятся 14 последних.

## 24.10.2026 · Этап 3 — Google Календарь

1. **Без библиотеки `googleapis`:** вход и Calendar API — это несколько запросов, они сделаны через `fetch` (`server/src/google/api.ts`). Меньше зависимостей, а в тестах вместо сети — поддельный Google (`server/src/google/fake.ts`).
2. **Права — три, минимальные:** `calendar.events.readonly` (видеть занятость), `calendar.calendarlist.readonly` (список календарей), `calendar.app.created` (свой календарь «Мой университет» и события только в нём). Чужие календари сервис не меняет.
3. **Занятость — только то, что Google считает занятым:** без событий «свободен», отклонённых встреч, отменённых, «рабочего места» и дней рождения. Событие на весь день, отмеченное как занятое (например, отпуск), закрывает весь день. Календари «только занятость» пропускаются — их событий не прочитать.
4. **Занятость кэшируется на 5 минут и хранится в базе:** без интернета или с истёкшим доступом сервис работает с последними данными и показывает, когда они получены.
5. **Доступ хранится в локальной базе** (`data/`, не попадает в git). Истёк — сервис помечает «войти заново»; вход повторяет тот же адрес.
6. **Синхронизация:** сначала правки пользователя в Google, потом план → календарь, потом свежая занятость. Запускается при старте, каждые 15 минут и через 3 секунды после любого изменения через API. События — без напоминаний, с пометкой занятия внутри (`extendedProperties`), чтобы находить свои.
7. **Перенос в Google принимается как ручной;** если так нарушаются правила — вопрос «оставить или вернуть». **Удаление в Google — вопрос** «пропустить или вернуть»; пока нет ответа, событие не возвращается.
8. **Удалили календарь «Мой университет»** — при следующей синхронизации он создаётся заново со всеми занятиями.
9. **В Google ничего не пишется, пока нет подтверждённого семестра.**
10. **Особенность каркаса, проявившаяся на настоящем календаре:** движок выбирает места, свободные в большинстве недель (методология, цель «стабильность»), поэтому даже одна разовая встреча может сдвинуть постоянное время или день дисциплины на весь семестр, если рядом есть столь же удобное, но полностью свободное место. Это не нарушение правил, но стоит посмотреть на твоём реальном календаре.

## 25.10.2026 · Этап 4 — технический интерфейс

1. **Без дизайна, но пригодный для жизни на 3–5 дней:** простые экраны на React без библиотек интерфейса и роутера (адрес экрана — `#today`, `#schedule` …). Дизайн — этап 5, логика экранов (запросы, состояние) остаётся.
2. **Форматы времени и длительностей — из движка,** часовой пояс — из настроек, так интерфейс и сервер пишут время одинаково.
3. **После любого действия все экраны перезагружают данные;** раз в минуту — тоже (пропуски, конфликты). Если сервер не ответил — повтор через 3 секунды.
4. **Таймер считает сам между запросами,** а точное состояние берёт с сервера: перезагрузка страницы ничего не сбивает (проверено в браузере). Смена фазы Помодоро — короткий звуковой сигнал и время в заголовке вкладки.
5. **Мастер первой настройки помнит шаг в браузере** — вход в Google уводит со страницы и возвращает.
6. **Много пропусков — одно действие** «оставить все как есть»: после отпуска не нужно разбирать 30 вопросов по одному.
7. **Тестовый экземпляр** (`node scripts/test-instance.mjs`, запуск «test»): своя временная база, порты 4200/5174, Google отключён, часы перематываются (`POST /api/dev/clock`) — только в этом режиме. Настоящая база и Google не затрагиваются.

## 25.10.2026 · Этап 5 — дизайн

1. **Макеты пропущены по твоей просьбе** («делай дизайн без моих проверок»): экраны сверстаны сразу, проверены на тестовом экземпляре в узком окне и в настольном размере 1440 px.
2. **Своя дизайн-система на CSS, без Tailwind и UI-библиотек** (`web/src/styles.css`, `web/src/ui.tsx`): токены цвета (белый, синий `#4f5fe8`, фиолетовый `#7b5ce8`), радиусы, тени; карточки, кнопки, метки, варианты выбора, пустые состояния и «заготовки» при загрузке. Иконки — `lucide-react`.
3. **Шрифты лежат в проекте** (Inter и Manrope через `@fontsource-variable`): сервис локальный и должен выглядеть одинаково без интернета.
4. **У каждой дисциплины свой цвет** — по порядку создания, включая архивные, чтобы цвет не «прыгал». Палитра из 8 цветов проверена валидатором различимости: соседние цвета различаются и при нарушениях цветового зрения; рядом с цветом всегда стоит название.
5. **Звуки природы синтезируются в браузере (Web Audio), а не берутся из записей:** дождь, море, лес с птицами, костёр, ручей, тихий шум. Ничего не нужно скачивать и проверять лицензии, звук бесшовный и работает без интернета. Микшер: громкость каждого звука и общая, «замолкать в перерыв», «как в прошлый раз» (настройки — в браузере).
6. **Перенос занятия перетаскиванием** в сетке недели: шаг 15 минут; если нарушаются правила — открывается панель занятия со списком нарушений и кнопкой «Перенести всё равно».
7. **Статистика:** плитки показателей, полосы «факт из плана» по дисциплинам и график чистой учёбы по неделям (по дисциплинам, с подсказкой при наведении); у полос и графика есть табличный вид.
8. **Найдено и исправлено при проверке:** страница застревала на «Жду, пока запустится сервер», если сервер стартовал дольше 3 секунд (повтор был один); на узком окне страница прокручивалась вбок; таймер показывал «89:37» вместо «1:29:37».

## 25.10.2026 · Этап 6 — запуск и особые случаи

1. **Рабочий режим — один процесс на http://localhost:4100:** сервер сам отдаёт собранный интерфейс (`OU_SERVE_WEB=1`). Адрес возврата из Google остаётся прежним (`/auth/google/callback` на 4100), поэтому в Google Cloud ничего менять не нужно; после входа браузер возвращается на 4100.
2. **Ярлык запускает `node --import tsx server/src/system/launcher.ts open`:** если интерфейс старше исходников — пересобирает его, если сервер не работает — запускает его в фоне без окна (журнал — `data/logs/server.log`), затем открывает «Сегодня» в браузере по умолчанию. Ошибку запуска показывает окном Windows, потому что консоль ярлыка свёрнута и сразу закрывается.
3. **Автозапуск — тот же ярлык в папке автозагрузки пользователя,** без служб, планировщика и прав администратора. Ярлык и автозапуск переключаются в «Настройках» → «Запуск» и командами `npm run app:install` / `app:uninstall`. Напоминаний нет — по-прежнему.
4. **Значок рисуется скриптом** (`scripts/make-icon.mjs` → `web/public/favicon.ico`): шапочка на сине-фиолетовом квадрате; он же — значок вкладки.
5. **Защита от чужих страниц:** сервис теперь работает в фоне постоянно, поэтому запросы, которые что-то меняют, принимаются только со страниц на `localhost`. Открытый в браузере чужой сайт не сможет, например, отключить Google или пропустить занятие.
6. **Сон и выключение во время занятия:** сервер раз в 30 секунд отмечается в базе; разрыв больше 2 минут — сон, выключение или остановка сервиса (в том числе до запуска). Таймер встаёт на паузу с последней отметки; в режиме занятия видно, с какого по какое время, и есть «Я занимался — засчитать». Пока идёт занятие, страница просит браузер не гасить экран (Wake Lock), чтобы компьютер не уснул от бездействия.
7. **Закрытый браузер:** занятие продолжается (так задумано с этапа 2). Но если время занятия вышло, а от страницы больше 10 минут не было запросов, таймер встаёт на конце занятия — иначе забытое занятие насчитало бы часы учёбы.
8. **Часовой пояс:** расписание ведётся в поясе из настроек. Если часы компьютера в другом поясе, сверху подсказка: сколько сейчас у тебя и в поясе расписания. Перестраивать семестр под новый пояс сервис сам не будет.

9. **Двойной запуск:** ярлык часто нажимают дважды, а автозапуск может совпасть с нажатием. Сервер запускает только тот запуск, который первым взял замок `data/launch.lock`, остальные ждут его и просто открывают браузер; второй сервер, если всё же стартует, видит занятый порт и тихо выходит. База ждёт до 5 секунд, если её на мгновение занял другой процесс.

## 25.10.2026 · Дизайн 2 — «вау»

1. **Живой фон вместо однотонного:** за интерфейсом медленно плывут пятна сине-фиолетового «сияния» и лежит едва заметная точечная сетка; карточки — полупрозрачное белое стекло, сквозь которое чуть видно фон. Пятна — мягкие радиальные градиенты без `blur` и `backdrop-filter`, двигаются только через `transform`, чтобы не грузить компьютер во время 90-минутного занятия.
2. **«Сегодня» — герой-блок и линия дня:** у следующего занятия яркий градиент с орбитами, плашками времени и живым отсчётом «до начала» (или «до конца», если идёт); когда пора начинать — кнопка мягко «дышит» светом. Занятия дня — на вертикальной линии с точками: проведённое отмечено галочкой, ближайшее пульсирует. Кольцо «Как идёт семестр» показывает, какая доля плана в часах уже пройдена.
3. **Режим погружения тёмный:** пока идёт занятие и открыт его экран, весь интерфейс «выключает свет» — тёмно-синий фон со звёздами, светящееся кольцо таймера с делениями и бегущей точкой, ореол за кольцом медленно «дышит» (около 8 секунд на вдох-выдох). В перерыв кольцо и ореол становятся бирюзовыми. После занятия — снова светлый интерфейс.
4. **Маленький праздник после итога:** «Занятие засчитано! +1 ч 15 мин чистой учёбы — так держать» и конфетти из углов экрана. Это не напоминание и не уведомление — появляется только в ответ на твоё действие.
5. **Мелкие движения:** карточки появляются по очереди, полосы прогресса и столбики графика «наливаются», по главной кнопке пробегает блик, иконки меню чуть поворачиваются при наведении, точка «сейчас» в расписании пульсирует. У заголовка каждого раздела — значок раздела; у приветствия — значок времени суток.
6. **Если в Windows включено «Уменьшить анимацию»**, всё движение отключается: фон стоит, конфетти нет, похвала просто показывается.
7. **Телефон и узкое окно:** меню — одна строка, листается вбок; герой-блок и кольцо семестра сами перестраиваются, если им мало места (container queries), а не только по ширине экрана.
8. **Найдено и исправлено при проверке:** в узкой колонке цифры в «Как идёт семестр» наезжали на подписи; при средней ширине окна отсчёт сжимал текст героя в узкую полосу; конфетти летели бы вдвое быстрее на мониторах 144 Гц (физика теперь по времени, а не по кадрам); при «Уменьшить анимацию» похвала была бы невидимой.
